# PRAG Vision Feeding System

3S Robotics의 협동로봇 기반 비전 피딩(pick & place) 설비 제어 프로그램입니다. 카메라로 박스 안 제품을 인식(YOLO 세그멘테이션)해서 좌표를 계산하고, 협동로봇이 픽업 → 파기(배치)까지 자동으로 수행합니다.

## 이 시스템의 소개

### 사용자가 사진 수백 장을 직접 찍을 필요가 없음

일반적인 YOLO 커스텀 학습은 제품마다 다양한 각도·조명·배경으로 촬영한 사진을 수백 장 모으고, 하나하나 바운딩박스/마스크를 라벨링해야 합니다. 현장 작업자가 하기엔 비현실적인 작업량입니다.

이 시스템은 이 과정을 자동화합니다.

1. **제품 템플릿 등록(8~10장)** — 설정 화면 "제품 목록 관리"에서, 새 제품을 박스 안에 놓고 위치·방향을 바꿔가며 8~10장만 촬영하면 됩니다. 촬영된 이미지는 자동으로 배경 제거(마스크 추출)되어 "제품 템플릿"으로 저장됩니다(`VISION/shape_capture_and_add_qt.py`).
2. **학습 데이터 자동 합성(제품당 200장)** — "비전 AI 학습"을 실행하면, 이 소수의 템플릿 이미지를 화이트/블랙/실제 촬영 배경/제품 자체 텍스처 배경 위에 무작위 위치·개수(15~30개)로 합성해서 라벨(세그멘테이션 마스크)까지 자동 생성합니다(`VISION/auto_yolo_seg_qt.py`). 사람이 라벨링할 필요가 전혀 없습니다.
3. **제품별 단독 모델 자동 학습** — 합성된 데이터로 제품마다 독립된 YOLO 세그멘테이션 모델(`best_<제품명>.pt`)을 자동 학습하고, UI에서 제품을 선택하면 해당 모델로 즉시 전환됩니다.

즉, **작업자는 신제품이 추가될 때마다 사진 8~10장만 찍으면**, 실제 학습에 필요한 수백 장 분량의 라벨링된 데이터셋과 전용 인식 모델이 몇 분~몇십 분 내로 자동 준비됩니다. 별도의 비전/AI 전문 인력 없이 현장에서 제품 추가·교체에 대응할 수 있는 게 이 시스템의 핵심 강점입니다.

### 그 외 강점

- **제품별 독립 모델** — 제품 하나가 오검출을 일으켜도 다른 제품 모델에는 영향 없음. 신제품 추가 시 기존 모델 재학습 불필요.
- **하드웨어 자동 감지 학습** — GPU 유무를 자동 감지해 배치 크기/워커 수를 최적화(`auto_yolo_seg_qt.py`), 개발 PC(GPU)와 고객 PC(CPU) 양쪽에서 동일 코드로 학습 가능.
- **현장 자가 유지보수** — ROI, 신뢰도 임계값, 캘리브레이션, 로봇 좌표까지 전부 터치 UI에서 설정/저장 가능해 설치 위치나 그리퍼가 바뀌어도 코드 수정 없이 대응.

## 하드웨어 구성

(`프래그 비전시스템 구성도.pdf` 기준)

- **협동로봇** — 피킹/파기 동작 수행
- **비전 시스템** — 박스 상단에 장착된 카메라, 제품 인식용
- **키링 박스** — 로봇이 집는 제품이 담기는 박스, 하단 진동/흔들기 장치 포함
- **컨베이어 + 터치패널** — 제품 이송 및 로컬 조작
- **터치 모니터** — 메인 UI(`ppap_main.py`) 표시용
- **NFC 칩 라이팅기** — 제품 칩 기록
- **타워 램프** — 상태 표시등(적/황/청)
- **비상스위치** — 안전 정지

## 소프트웨어 구성

PyQt5 기반 데스크톱 앱(`ppap_main.py`)이 메인 진입점이며, 아래 모듈을 오케스트레이션합니다.

```
ppap_main.py           # 메인 UI + 상태 관리 + 작업 루프(JobThread)
ROBOT_CONTROL/          # 로봇 TCP 소켓 통신 (29999 제어포트 / 30001 상태·모션포트)
VISION/                  # 카메라 스트리밍, YOLO 세그멘테이션 추론, 캘리브레이션, AI 학습
IO/                      # Modbus TCP 기반 IO 모듈 (진공/블로우/램프/부저/PLC 신호)
DB/                      # SQLite 기반 설정값(포즈, 비전 신뢰도 등) 저장
UI/                      # PyQt Designer로 생성된 화면 레이아웃(.ui → _ui.py)
```

### 주요 흐름

- **로봇 통신**: `ROBOT_SEND`가 29999(제어 명령)·30001(상태/좌표 폴링) 두 소켓을 관리. `RobotStatusThread`가 백그라운드에서 상태를 폴링해 변경분만 UI에 emit.
- **작업 루프**: `on_start_button_clicked` → `JobThread` → `job_command()`가 HOME → 비전 촬영 → 픽 → 파기를 반복. IO 8번 핀(PLC 수량 도달 신호) 감지 시 자동 정지.
- **비전**: `VisionMain` → `VisionWorker`(QThread) → `YOLOToRobotQt` → `YOLOSegDetector`(ultralytics YOLO). 제품별로 `best_<제품명>.pt` 단독 모델을 `VISION/runs_seg/`에 저장하고, UI에서 선택한 제품 모델을 동적으로 교체(`change_target_model`)해서 사용.
- **AI 학습**(`VISION/auto_yolo_seg_qt.py`): 제품 템플릿 이미지를 다양한 배경에 합성해서 학습 데이터를 자동 생성 후 YOLO 세그멘테이션 학습. 배경 구성비는 화이트:블랙:실제배경:템플릿배경 = 2:2:3:3 + 순수배경(네거티브 샘플) 별도.
- **DB**: `robot_system.db`(SQLite)에 홈/픽/플레이스/캘리브레이션 포즈, 비전 신뢰도 등을 저장. 앱 시작 시 로드, 설정 화면에서 저장.

## 실행 방법

```
python ppap_main.py
```

`requirements.txt` 참고해서 의존성 설치 (GPU(CUDA 12.8) 환경 기준):

```
pip install -r requirements.txt
```

CPU 전용 환경(고객 PC 등)에 배포할 경우 `torch`/`torchvision`은 CPU 빌드로 별도 설치 필요.

### ⚠️ import 순서 주의

`ppap_main.py` 최상단에서 `torch`/`ultralytics`를 `PyQt5`보다 **반드시 먼저** import해야 합니다. 순서가 바뀌면 `torch/lib/c10.dll` 로딩 중 access violation으로 프로그램이 죽습니다(파이썬 예외가 아니라 Windows 레벨 크래시라 콘솔에 아무 로그도 안 남을 수 있음).

## 배포(exe) 빌드

`배포_명령어.txt`에 PyInstaller 빌드 명령이 정리되어 있습니다. 핵심 옵션:

- `--contents-directory .` — PyInstaller 6.x의 `_internal` 서브폴더 구조를 비활성화하고, 데이터 파일을 exe 바로 옆에 풀어서 코드의 `Path(sys.executable).resolve().parent` 기준 경로 탐색과 호환되게 함
- `--runtime-hook "hook-torch-first.py"` — PyInstaller가 자동 삽입하는 PyQt5 런타임 훅보다 먼저 torch를 강제 import해서 위의 DLL 충돌을 exe 안에서도 방지
- `--collect-all torch` — torch 전체 번들 (분석 단계가 오래 걸리는 원인, 정상)
- 다수의 `--exclude-module` — 이 프로젝트와 무관하게 같은 Python 환경에 설치된 다른 프로젝트용 패키지(jax, mujoco, open3d, mediapipe, transformers 등)를 제외해서 빌드 용량/시간 절감

빌드 후 코드(`.py`)를 수정했다면 **반드시 재빌드**해야 합니다 — `dist/` 안의 `.py` 파일을 직접 고쳐도 반영되지 않습니다(PyInstaller가 빌드 시점에 컴파일한 바이트코드를 우선 로드하기 때문). `.yaml`/`.pt`/이미지 등 순수 데이터 파일은 `dist/` 안에서 직접 수정해도 즉시 반영됩니다.

`--clean` 옵션은 캐시를 지우고 처음부터 다시 분석하므로 매번 훨씬 오래 걸립니다. 소스만 바뀐 경우 `--clean` 없이 재빌드하면 PyInstaller가 변경된 파일만 다시 반영하면서 캐시를 재사용해 더 빠릅니다.

## 사용자 매뉴얼 요약

전체 내용은 `PRAG_사용자메뉴얼 v0.01.pdf` 참고. 핵심만 정리:

- **메인 화면**: 로봇 상태 표시 / 비전 미리보기 / 로그 / 로봇 제어(전원, 작업 시작·정지·일시정지, 홈 이동) / 설비 제어(진공, 박스 흔들기, 부저, 리셋)
- **설정 화면**(우측 상단 로고 클릭): 비전 검출 영역(ROI), 비전 검출 신뢰도, 비전 캘리브레이션, 비전-로봇 캘리브레이션, 제품 목록 관리, 비전 AI 학습, 로봇 좌표(홈/픽/플레이스/캘리브레이션 포즈, 그리퍼 길이, 마커 위치) 설정
- **자동 운전 절차**: 로봇 홈 이동 → 비전 촬영 → 물체 확인 → 좌표 이동 → 흡착 → 파기 반복. 비전 인식/흡착 실패 시 박스 흔들기, 3회 연속 실패 시 작업 종료 팝업
- **검은색 제품 학습 시 주의**: 흰 배경에서 템플릿 촬영 → 학습은 흰 배경 제거 후 진행 → 실사용 시에도 검정 제품 작업 시엔 박스 바닥에 흰 배경을 깔아야 인식됨
- **안전**: 안전문 열림 시 안전 릴레이 동작 → 로봇 정지/전원 꺼짐 → 컨베이어 정지. 복귀는 문 닫음 → 비상정지 복귀 → PC에서 로봇 리셋 → 전원 켜기 → 작업 시작 순서

## 알려진 이슈 / 트러블슈팅 메모

- **디버그 모드에선 뜨는데 일반 실행 시 UI가 안 뜸** → torch/PyQt5 import 순서 문제. 위 "import 순서 주의" 참고.
- **exe에서 `sqlite3.OperationalError: unable to open database file`** → PyInstaller 6.x `_internal` 폴더 이슈. `--contents-directory .`로 해결.
- **로봇 정지 버튼을 눌러도 상태 표시가 "로봇 동작 중"에 그대로 머무름** → 하드웨어 `running` 비트 갱신을 기다리지 않도록 정지 시 `self.running = False`를 즉시 반영하도록 수정됨(`on_stop_button_clicked`, PLC 8번 핀 자동정지 경로 모두 적용).
- **UI에서 제품을 선택해도 다른(이전) 제품 모델이 계속 로드됨** → `VisionWorker.change_model()`이 존재하지 않는 메서드(`load_model`)를 찾다 실패하고 잘못된 속성명(`weight_path`)에 값을 저장한 뒤 stale한 설정으로 `reload_config()`를 호출하는 버그였음. `YOLOToRobotQt.change_target_model()`을 직접 호출하도록 수정됨.
- **AI 학습 결과 인식률이 낮음 / 바닥을 제품으로 오인식** → 학습 데이터 배경 합성 비율이 원인일 가능성이 높음. 제품 템플릿 이미지를 배경으로 확대해서 쓰는 방식(템플릿 배경)의 비중이 너무 높으면(50%+) 모델이 애매한 신호를 학습해 오검출이 늘어남. 화이트:블랙:실배경:템플릿 = 2:2:3:3 비율(+ 순수 배경 네거티브 샘플 소수)이 검증된 안정적인 비율.
- **Git에서 커밋 직후에도 다수 파일이 "수정됨(M)"으로 표시됨** → CRLF/LF 줄바꿈 정규화 문제. `.gitattributes` 부재가 원인. (현재 `.gitignore`는 비어 있어 모든 파일이 추적 대상.)
